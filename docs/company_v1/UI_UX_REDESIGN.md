# 회사편 v1 UI/UX 재설계

상태: active design contract  
기준일: 2026-08-03  
적용 시점: Phase 7 Frontend부터. Phase 0에는 구현하지 않는다.

## 1. 목적

병원편은 기능이 누적되면서 우측 패널에 플레이어 정보, 성적 상태, 캐릭터 이미지, NPC 기본정보, NPC 수치, 마인드 모니터, 관계 기록, 플레이어 속마음, 앱·재개·리셋·피드백 버튼이 모두 세로로 쌓였다. 기능은 많지만 매 턴 판단에 필요한 정보와 기록·관리 정보가 같은 우선순위로 노출되어 화면이 길고 복잡해졌다.

회사편은 기능을 줄이는 대신 다음 원칙으로 정보 구조를 다시 구성한다.

1. 플레이 중 필요한 정보만 항상 보인다.
2. 상세 기록과 관리 기능은 접거나 별도 화면으로 분리한다.
3. 서사 읽기를 화면의 최우선 작업으로 둔다.
4. 선택지는 쉽게 읽고 누를 수 있어야 한다.
5. 데스크톱과 모바일이 같은 패널을 억지로 공유하지 않는다.
6. 상태 수치는 의미가 있을 때만 강조한다.
7. 이미지와 장식이 텍스트 읽기를 방해하지 않는다.

## 2. 병원편 UI에서 확인된 문제

### 2.1 우측 패널 과밀

현재 병원편 우측 패널에는 다음 항목이 연속으로 배치된다.

- 플레이어 카드
- 사정 게이지
- 캐릭터 이미지
- 캐릭터 기본정보
- NPC 상태
- 마인드 모니터
- 관계 기록
- 플레이어 속마음
- 상식개변 앱
- 플레이 재개
- 리셋
- 피드백

모든 항목이 항상 같은 폭과 시각적 무게를 가져 중요한 정보가 묻힌다. 관계 상세 기록처럼 자주 확인하지 않는 데이터도 상시 패널 안에 존재한다.

### 2.2 정보 중복

장소·시간·플레이어 상태가 본문, 플레이어 카드, 별도 상황판에 중복될 수 있다. NPC의 감정·수치·관계·마인드 모니터도 서로 가까운 의미를 반복한다.

### 2.3 조작과 정보의 혼합

앱, 재개, 리셋, 피드백이 캐릭터 상태 아래에 같은 버튼 형식으로 놓여 있다. 플레이 행동과 시스템 관리 행동의 구분이 약하다.

### 2.4 모바일에서 긴 세로 이동

데스크톱용 우측 패널을 모바일에서 아래로 이어 붙이면 이미지·상태·기록을 지나야 선택지나 핵심 조작에 도달할 수 있다.

### 2.5 선택지 영역의 과부하

선택지 원문은 길 수 있고, 과감·직접 실행·차단 등의 메타가 함께 붙으면 버튼 한 개가 지나치게 복잡해진다. 선택지가 4개여도 각 버튼의 높이가 계속 늘어날 수 있다.

## 3. 회사편 정보 우선순위

### P0 — 항상 보여야 하는 정보

- 현재 서사
- 현재 대화
- 선택지 4개
- 현재 등장 메인 NPC 이름과 이미지
- 현재 장소·시간대
- 현재 업무 또는 장면 목적 한 줄
- 활성 CSA 중 현재 장면에 적용되는 규정 요약
- 입력·생성·저장 상태

### P1 — 한 번의 조작으로 열 수 있는 정보

- NPC 호감도·상식수용도·성적흥분도
- 마인드 모니터
- 플레이어 상태와 복장
- NPC 복장·자세
- 관계 단계와 핵심 경계
- 사정 게이지
- 현재 업무 상세

### P2 — 별도 화면이나 상세 모달

- 전체 관계 기록
- 성적 경험 횟수
- 전체 활성 CSA 목록
- 회사 조직도
- 사옥 지도
- 플레이 기록
- 버전·디버그 정보
- 리셋
- 피드백 이력

## 4. 데스크톱 레이아웃

### 4.1 기본 3영역

```text
┌─────────────────────────────────────────────────────────────┐
│ 상단 상태 바: 장소 · 시간 · 현재 업무 · 저장 상태          │
├──────────────────────────────┬──────────────────────────────┤
│                              │ 현재 인물                    │
│ 서사/대화 스트림             │ 이미지                       │
│                              │ 핵심 상태 요약                │
│                              │ 적용 규정 요약                │
│                              │ [상세 보기]                   │
├──────────────────────────────┴──────────────────────────────┤
│ 선택지 4개 + 직접 입력                                      │
└─────────────────────────────────────────────────────────────┘
```

- 중앙 본문은 가장 넓은 영역을 사용한다.
- 우측은 280~320px 고정 폭을 넘기지 않는다.
- 우측 패널은 핵심 카드 3개까지만 기본 노출한다.
- 기록·관리 기능은 상단 메뉴 또는 상세 모달로 이동한다.

### 4.2 상단 상태 바

한 줄에 다음만 표시한다.

- `📍 5층 마케팅팀`
- `오후`
- `업무: 캠페인 수정안 검토`
- 저장 중/저장 완료/오프라인 경고

게임 버전과 개발 정보는 메뉴 안으로 이동한다.

### 4.3 우측 인물 패널

기본 노출:

1. 캐릭터 이미지
2. 이름·직급·팀
3. 호감·수용·흥분의 짧은 상태 칩
4. 현재 자세·복장·행동 한 줄
5. 현재 장면 적용 CSA 최대 2개 요약
6. `상세 상태` 버튼

기본 화면에서 숨김:

- 전체 관계 횟수
- 최초 경험 턴
- 세부 사정 위치 횟수
- 긴 캐릭터 배경
- 전체 마인드 모니터 원문

### 4.4 상세 상태 Drawer

우측에서 열리는 drawer 또는 modal에 다음을 배치한다.

- 마인드 모니터
- 관계 단계
- 경계와 최근 거절
- 복장·자세
- 성적 기록 상세
- 플레이어 상태
- 사정 게이지

한 번에 모든 섹션을 펼치지 않고 accordion을 사용한다.

## 5. 모바일 레이아웃

### 5.1 기본 구조

```text
상단 compact bar
현재 인물 compact card
서사/대화 스트림
선택지 4개
하단 고정 navigation
```

모바일에서 별도 우측 패널을 만들지 않는다.

### 5.2 하단 고정 navigation

최대 4개 탭:

- 이야기
- 인물
- 앱
- 더보기

`더보기` 안에 기록, 지도, 피드백, 리셋을 둔다.

### 5.3 선택지

- 화면 하단에 고정하지 않고 본문 완료 후 자연스럽게 이어서 표시한다.
- 키보드가 열리면 선택지와 입력창이 겹치지 않아야 한다.
- 선택지 버튼 최소 높이 48px.
- 버튼 본문은 최대 2줄.
- 전체 원문은 길게 누르기, 펼치기 또는 상세 tooltip으로 확인한다.
- 클릭·저장에는 전체 원문을 사용한다.

## 6. 상태 표시 원칙

### 6.1 숫자보다 상태 언어 우선

기본 화면:

- 호감 62 → `호감 높음`
- 상식수용도 41 → `규정에 아직 어색함`
- 흥분도 78 → `강하게 흥분함`

상세 화면에서만 정확한 숫자를 보여준다.

### 6.2 변화가 있을 때만 강조

- 변화 없는 수치는 중립 표시
- 이번 턴 변화가 있으면 `+3`, `-2`를 잠시 표시
- 변화 강조는 다음 턴까지 유지하지 않는다.
- 색상만으로 상승·하락을 구분하지 않고 아이콘과 텍스트를 함께 쓴다.

### 6.3 성적 상태의 노출

사정 게이지는 항상 큰 카드로 노출하지 않는다.

- 0~49: 상세 상태 안에만 표시 가능
- 50~84: 인물 패널 또는 플레이어 상태에 작은 상태 칩 표시
- 85~99: 경고 단계 표시
- 100/pending: 상단 또는 선택지 근처에 명확한 경고 표시

## 7. CSA UI

### 7.1 현재 장면 요약

기본 화면에는 현재 장면에 적용되는 CSA만 최대 2개 표시한다.

예:

```text
적용 규정
• 보고 중에는 상사의 무릎에 앉는다
• 회의 중 상의 착용은 선택 사항이다
```

### 7.2 전체 앱 화면

별도 앱 화면에는 다음 탭을 둔다.

- 활성 규정
- 새 규정 만들기
- 슬롯·레벨
- 기록

규정 카드에는 다음만 우선 표시한다.

- 한 줄 규정 요약
- 강도
- 실행 방식: 필수/규범
- 적용 대상
- 활성 여부

actor/target/trigger/duration 전체 계약은 상세 펼치기에서만 보인다.

### 7.3 mandatory와 normative 표시

- mandatory: `필수 실행`
- normative: `규범 · 거부 가능`

색상만으로 구분하지 않는다.

## 8. 선택지 UX

### 8.1 시각 구조

각 버튼은 다음 구조를 가진다.

```text
[아이콘/종류] 선택지 요약
필요할 때만 짧은 보조 문구
```

종류별 표시:

- normal: 별도 배지 없음
- csa_direct: `규정 직접 실행`
- bold: `과감 행동 · 성공 가능성`
- blocked: 비활성 + `현재 불가능`

### 8.2 확률 표시

- 실제 bold에만 표시한다.
- normal에는 확률을 표시하지 않는다.
- csa_direct에는 확률을 표시하지 않는다.
- blocked에는 확률 대신 불가능 이유를 한 줄 표시한다.

### 8.3 버튼 원문과 저장

- 모델이 생성한 전체 원문은 데이터로 유지한다.
- 버튼은 가독성을 위해 2줄까지 축약 가능하다.
- 클릭, 기록, Commit에는 전체 원문을 사용한다.
- 축약문을 다시 모델 입력으로 사용하지 않는다.

## 9. 시스템 조작 분리

### 플레이 행동

- 선택지
- 직접 입력
- 상식개변 앱 사용

### 시스템 관리

- 플레이 기록
- 피드백
- 리셋
- 버전 정보
- 설정

두 종류의 버튼을 같은 행이나 같은 강조색으로 배치하지 않는다.

리셋은 `더보기 → 게임 관리 → 리셋`의 2단계 안쪽에 둔다.

## 10. 로딩과 오류 상태

각 단계의 상태를 하나의 메시지로 표현한다.

- `이야기 생성 중`
- `상태 정리 중`
- `저장 중`
- `저장 완료`

Story 스트리밍이 시작되면 로딩 spinner 대신 실제 텍스트를 우선 표시한다.

오류 시:

- Story 실패: 입력을 보존하고 재시도 제공
- Extract 실패: Story는 유지하고 warning 후 재시도 가능
- Commit 실패: Story와 선택 결과를 보존하고 저장 재시도
- 이미지/TTS 실패: 게임 진행을 막지 않음

## 11. 이미지와 TTS

### 이미지

- 이미지가 없을 때 빈 큰 박스를 유지하지 않는다.
- 다중 NPC 장면은 메인 화자 이미지를 우선한다.
- 이미지 변경 시 레이아웃 높이가 갑자기 흔들리지 않게 aspect-ratio를 고정한다.

### TTS

- 자동재생 여부는 설정으로 분리한다.
- 현재 발화자·재생 상태를 작은 indicator로 표시한다.
- TTS 실패는 대화 표시를 막지 않는다.
- 서사 문장은 기본적으로 TTS 대상에서 제외하고 캐릭터 대사만 읽는다.

## 12. 접근성과 기본 품질

- 버튼 최소 터치 크기 44~48px
- 키보드만으로 선택지 이동·실행 가능
- focus outline 제거 금지
- 색상 대비 확보
- 상태 변화는 aria-live로 알림
- 애니메이션 감소 설정 지원
- 긴 대사·긴 한국어 단어의 overflow 방지
- 작은 화면에서 가로 스크롤 금지

## 14. 수용 기준

- 첫 화면에서 서사와 선택지가 가장 높은 시각적 우선순위를 가진다.
- 우측 기본 패널은 스크롤 없이 핵심 정보 대부분을 보여준다.
- 관계 상세·기록·리셋은 기본 화면에 상시 노출되지 않는다.
- 모바일에서 이야기와 선택지 사이에 긴 상태 패널이 끼지 않는다.
- 선택지 전체 원문은 저장되지만 버튼은 최대 2줄로 읽을 수 있다.
- 상태 변화는 숫자·아이콘·텍스트로 함께 전달한다.
- Story, Extract, Commit, 이미지, TTS 오류가 서로 독립적으로 표시된다.

## 15. 금지

- 병원편 sidebar DOM을 통째로 복사하지 않는다.
- 기능이 추가될 때마다 우측 패널에 새 section을 영구 추가하지 않는다.
- 모든 상태를 항상 숫자로 노출하지 않는다.
- 시스템 관리 버튼을 플레이 행동과 같은 시각적 위계에 놓지 않는다.
- 모바일에서 데스크톱 우측 패널을 그대로 아래에 이어 붙이지 않는다.
